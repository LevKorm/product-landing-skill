Every phase leaves a file.

So the next chat, or you next week, doesn’t start from zero. And nothing reaches code before the template check.

  1. Facts and brief

    Reads memory, docs and code. Every claim gets a source. Anything it can’t verify becomes an open question.

    docs/landing/brief.md

  2. Visitor questions

    Keeps only the questions this visitor has, and picks a form for each one from a menu with conditions.

    section map

  3. Signature moment

    Completes “a person does ___, and ___ happens”, then finds the visual that shows it with the least text.

    brief.md · mechanic

  4. Visual language

    Colors with one meaning each, fonts and devices taken from the product’s world. Checked against AI clichés.

    design plan

  5. Template check

    Each section names the fact that demands its form. “It worked on another landing” doesn’t count.

    fact column

  6. Build and feedback

    One HTML file to review as a Claude artifact. Big turns become versions. Your taste carries to the next product.

    index.html · taste-profile.md

  7. Ship

    Mobile pass, OG image and favicon, Vercel deploy, and an insert-only Supabase waitlist when the product needs one.

    build.sh · early_birds.sql
