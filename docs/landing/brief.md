# Landing brief: product-landing (Claude Code skill)

> Оновлено: 13.09.2026. Джерела: `README.md`, `skills/product-landing/**`, два сухі прогони скіла (картки для слів, API для рахунків), живий лендинг SOFA.

## One-liner
Скіл для Claude Code, який робить лендинг продукту з фактів про цей продукт і не пускає шаблонні секції, а потім деплоїть сторінку на Vercel.

## Headline-кандидати
1. The page takes the shape of the product. (уже в банері репо)
2. Landing pages that only fit your product.
3. Same skill. Different pages.

## Аудиторія
- Хто: люди, які будують продукти з Claude Code: інді-розробники, дизайнери-засновники, маленькі команди.
- Що використовують зараз: просять Claude «зроби лендинг», беруть шаблони, генератори сайтів, загальні дизайн-скіли.
- Рівень обізнаності: знають категорію (AI робить лендинги), не знають цей скіл.
- Категорія: знайома. Механіку показати за секунду, решта — чим інакше.
- Тип рішення: безкоштовно, open source, одна команда встановлення.
- Головне заперечення: «Claude і так робить лендинги, навіщо скіл?» і «всі AI-лендинги однакові».

## Головна механіка
Людина просить лендинг, і скіл перетворює факти її продукту на структуру, яка пасує лише цьому продукту: кожна секція називає факт, що її вимагає, а форми без факту вилітають.

Фірмовий момент: скелет сторінки, який перебудовується, коли перемикаєш продукт (менеджер вікон, полотно агентів, картки, API рахунків), а поруч речення «A person does ___, and ___ happens» заповнюється під кожен продукт. Клік на секцію показує факт, що її вимагає. Тест підміни: генератор шаблонів цей момент не забере, бо в нього форма однакова для всіх.

## Відмінності
Окрема таблиця порівняння не потрібна: категорія знайома, а різницю найкраще видно на одному прикладі «до / після». Форма: типова AI-карта секцій проходить перевірку на шаблонність для API рахунків і стискається з 7 до 3 + 2.

## Світ продукту
- Предмети: карта секцій, бриф `brief.md`, markdown-таблиця, slash-команда, файли, що лишає скіл.
- Одиниці: секції, питання відвідувача, факти, фази.
- Стани: форма з фактом (лишається), без факту (вилітає / замінюється), «лише з фактами» (пунктир), фірмовий момент.
- Жести: перемкнути продукт, запустити перевірку, скопіювати команду.
- Прийоми: стос блоків-секцій (як у банері), пунктир для умовних секцій, речення з пропусками, рядки перевірки ✓/✗ як лінтер.

## Тон і заборони
- Тон: прямий, інженерний, без пафосу.
- Не робимо: вигаданих відгуків, лічильника зірок, «trusted by», закріпленої схеми процесу, бенто, стіни фіч (усе це вже було в SOFA і тут не має факту).

## Карта секцій
| # | Питання відвідувача | Відповідь одним реченням | Форма | Який факт цього продукту вимагає цієї форми |
|---|---|---|---|---|
| 1 | Що це і чи для мене? | Скіл для Claude Code: сторінка бере форму продукту. | Заголовок, команда встановлення з Copy, GitHub; праворуч перемикач із 4 продуктів і скелет сторінки, що перебудовується | Результат роботи скіла — структура, різна для різних продуктів; це відчувається лише коли перемикаєш |
| 2 | Claude і так робить лендинги. Чим це інакше? | Типова карта проходить перевірку на шаблонність і стискається до того, що вимагають факти. | «До / після» на одному продукті: 7 типових секцій, кнопка «Run the template check», рядки отримують ✓/✗ з причиною | Відмінність скіла — сама перевірка; її видно на одному прикладі |
| 3 | Що саме воно зробить? | Сім фаз, кожна лишає файл. | Список фаз із файлом-чипом і одним рядком | Скіл реально лишає артефакти: бриф, карту, план, HTML, build.sh, SQL |
| 4 | Чи є справжній результат? | SOFA зроблена цим методом і живе на trysofa.vercel.app. | Скриншот у рамці + посилання; чесна примітка про сухі прогони | Є один публічний лендинг; решта не публічні або сухі прогони |
| 5 | Як поставити? | Дві команди в Claude Code або копія папки. | Команди з Copy, GitHub, MIT, вимоги | Open source, ставиться як плагін |

Перевірка на шаблонність:
- Інтерактив у першому екрані був у SOFA і в менеджері вікон. Тут інший факт: продукт видає структуру, тож показано структуру, а не інтерфейс. Лишаємо.
- «До / після» не використовувалось у попередніх лендингах. Факт: відмінність видно на одному прикладі.
- Список фаз — не закріплена панорама SOFA: процес тут лінійний і без гілок, тож простий список.
- Скриншот-доказ — лише справжній і публічний.

## Візуальна мова
- Колір: фон `#FFFFFF`, чорнило `#12151B`, другорядний `#5B6270`, лінії `#DDE1E7`, плитка `#F2F4F7`, акцент `#FF5A26` (текст на ньому `#12151B`), пунктир `#B9C0CA`. Акцент означає одне: «належить лише цьому продукту» (фірмовий момент, факт). Темна тема через токени.
- Шрифти: Schibsted Grotesk (заголовки і текст), IBM Plex Mono (команди, файли, лічильники секцій). Моно виправданий: продукт — інструмент розробника з командами й файлами.
- Композиція: ліворуч вирівняні заголовки, розділений перший екран, ширина 1200px, короткі екрани по одній ідеї. Не SOFA-центр.
- Іконки: Phosphor bold.
